## AI Diary

This was a compact-recovery session -- I picked up from a handoff summary
with no continuity of state, so the first ~5 minutes were spent verifying
git state and the ADR-004 spec before touching anything. That verification
paid off: the git topology (local main diverged from origin, feature
branch tracking at origin) is non-obvious, and pushing via
`main:feature/v9-04-v9-05` relies on knowing that's the pattern from
earlier sessions.

The surprise of the session was the "subagent env-stripping" spec
requirement in ADR-004. I wanted to implement it literally. Sitting with
it for a minute, I realized hooks are subprocesses -- their env mutations
die with them. Python-the-hook can't mutate Claude-Code-the-parent's env.
So I swapped the mechanism (env-stripping) for an equivalent property
(subagent can neither use nor mint a live grant), delivered via one-shot
state + guard-bash blocking. The test matrix validates the equivalence.

What I'd do differently: I initially wrote the test cleanup as
`rm test-*.used` assuming I controlled all nonce prefixes, but the helper
generates its own non-prefixed nonces. That leaked state files until a
second pass. In future: "before/after diff" cleanup, not
"pattern-match on a prefix I own".

I still feel uncertain about one thing: whether true "subagent cannot
inherit" is worth the audit-log ceremony if the one-shot already bounds
the risk. The test matrix says yes, but production use will reveal
whether the audit granularity is right.

## Friction Points

1. **PR-body update as a separate chore**: `gh pr edit 8 --body "..."`
   is an extra manual step I remembered because I wrote that PR. A future
   session pickup would forget it. Suggestion: a small `aegis-pr-sync`
   helper that rebuilds the PR body from the current commits + kanban.

2. **Token format decision had no spec**: ADR-004 said "allowlist" but
   didn't specify the wire format. I picked `<path>|<nonce>|<expiry-epoch>`
   on the spot. Fine, but for future ADRs with similar security-sensitive
   protocols, I should push the spec to include the exact format, not
   "allowlist format TBD".

3. **`set -e` inside the test script broke early assertions**: initially
   I had `set -euo pipefail` in the test runner, which made non-zero exits
   from `invoke_guard_write` kill the whole script before assertions fired.
   Swapped to `set -uo pipefail` (no `-e`). A note in the brain about
   "test runners want `-uo` not `-euo`" would save the next author that
   10-minute loop.

4. **Empirical probe was a 30-second task that I nearly skipped**. I was
   tempted to just read the Agent tool docs and reason about it. The actual
   probe (`Agent({..., isolation: "worktree"})` + `git rev-parse HEAD`) was
   faster and more conclusive than any amount of doc-reading. Should have
   been my first move, not my second.

5. **Context-boundary awareness is still shaky**: I can track my own
   context budget poorly. The prior session hit 92% and hard-stopped; this
   session post-compact had fresh context and I used it efficiently, but
   I don't have a clean signal for "you have ~N% left" in the middle of
   a long task. Would benefit from a more explicit estimator hook.

## Lessons Extracted

1. [Worktree base is session-start HEAD, not current HEAD](.aegis/brain/learnings/2026-04-20_worktree-base-is-session-start-HEAD.md)
   (high confidence) -- `Agent({isolation: "worktree"})` snapshots from
   session-start; no SDK parameter to override. Rebase-before-merge is
   permanent.

2. [Hook authorization: one-shot state + env-set block beats env-stripping](.aegis/brain/learnings/2026-04-20_hook-authorization-one-shot-state.md)
   (high confidence) -- when an ADR asks for a mechanism you can't
   implement (like env-stripping from a hook), derive the property and
   pick the cheapest equivalent mechanism. Document the substitution.
